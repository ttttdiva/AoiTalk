## 最優先ルール: 常時 commit & push（全作業共通）

- ファイルを変更する作業（実装・修正・整理・設定変更・ドキュメント更新など）では、ユーザーが明示的に `pushなし` または `commitなし` と言わない限り、検証・差分確認のうえ、対象差分だけを `add` → `commit` → `push` まで必ず完了させる。push 指示を待たず、デフォルトで push まで実行する。commit / push の前に確認を取らない。
- push 先は現在の checkout（通常 `main`）への直接 push を既定とする。ユーザーが今回の依頼でブランチ運用・PR を明示した場合のみそれに従う。
- `git status` で対象差分を確認し、ユーザーの無関係な変更を巻き込まない（`git add -A` は使わず、対象ファイルのみ stage する）。
- このルールは本ファイル内の他の記述（例:「commit・push はユーザーが明示した場合のみ」）に優先する。矛盾があっても常に本ルールに従い push まで完了する。
