# Web版の画面ペット

AoiTalkのログイン後のWeb画面に、Codex v2形式のペットを常時表示できます。設定は **設定 → 概要 → 画面のペット**、直接開く場合は `/settings#pet` です。ペット本体は **AoiTalkサーバー全体で1体の共通登録資産** です。ブラウザやユーザーごとに本体を登録する仕組みではありません。

## サーバーへの登録と移行

「サーバーにペットを登録」でCodex用ZIPを選ぶか、設定欄へドロップします。展開済みの場合は `pet.json` とスプライトシートの2ファイルを同時に選択してください。ZIPの外側に作業フォルダーがあっても扱えます。元のCodexファイルを書き換えたり、ZIP内のプログラムを実行したりすることはありません。

登録が成功すると「このサーバーにペットが登録済み」と名前が表示されます。同じサーバーへログインした別ブラウザ・別端末も自動的に登録を取得するため、ファイルの再登録は不要です。ブラウザを閉じたり、サイトデータを削除したり、AoiTalkの関連サービスを再起動してもサーバーの登録は残ります。サイトデータを削除した場合、通常どおりログインは必要です。

旧バージョンのブラウザ内だけにペットが残っている場合は、そのブラウザの設定に「以前のペットをサーバーへ移行」が表示されます。これを一度実行すると、ファイルを選び直さずサーバーへ登録できます。旧ペットは勝手にアップロードしません。既にサーバーに登録がある場合は移行で上書きせず、移行の同時実行でも一方だけが成功します。旧ブラウザのサイトデータを移行前に消した場合は、元のZIPから登録してください。

「サーバーのペットを置き換える」は全クライアントが使うペット本体の変更です。「サーバーのペット登録を削除」は確認後にサーバーの登録と本体を削除します。非表示ボタンは登録削除ではありません。正常な登録は、新しいファイルの検証や保存に失敗しても残ります。

## 他のブラウザ・端末への反映

ログイン後に登録情報を取得し、表示中のタブでは約15秒ごとに確認します。画面への復帰、ウィンドウのフォーカス、オンライン復帰、設定の再読み込みでも確認します。同一originのタブではBroadcastChannelで変更を通知します。バックグラウンドタブは復帰時に取得します。即時配信を保証するWebSocketではありません。

登録情報には版番号を持たせ、画像は変更時だけ取得してメモリで保持します。削除・置換前の画像URLを新しい登録として流用しません。APIは認証付き・キャッシュ禁止で、登録情報の取得失敗を「未登録」と誤表示しません。通信失敗時は確認できない旨を表示し、最後に取得した表示を保持する場合があります。再接続してサーバーを確認するまでは登録・置換・削除を行いません。

同時に複数ユーザーが明示的な置換や削除を行った場合、サーバーで最後に完了した保存切替・削除が反映されます。複数ペット管理や置換履歴はありません。

## 表示設定と既存操作

位置、サイズ、表示有無、視線、アニメーション抑制は、ブラウザのログインユーザー別表示設定です。これらだけをlocalStorageへ保存します。本体や「登録済み」の状態は保存しません。新しいブラウザでは標準サイズ128 px・表示有効で開始します。サイトデータの削除で表示設定は初期化されますが、登録ペットは消えません。ブラウザの保存領域が使えなくてもサーバー登録は利用でき、表示設定はその画面だけに適用できます。

ペットは設定画面だけでなく、ログイン後の通常WebUI全体にオーバーレイ表示されます。ドラッグで移動し、移動方向に合わせて左右へ走ります。クリックで手振り、矢印キーでも移動、Homeキーで位置初期化ができます。「×」または「ペットを表示する」で非表示にし、設定から再表示します。

表示サイズは64 / 96 / 128 / 160 / 192 pxです。狭い画面では表示位置とサイズを画面内に収めます。設定で10種類のモーションを確認でき、通常の視線はマウスに追従する16方向です。プレビューの視線は先頭方向です。

| 状態・操作 | モーション |
| --- | --- |
| 通常 | 待機、またはマウス方向への視線 |
| 送信処理・返答待ち・停止処理 | 返答待ち |
| 応答生成・ツール実行中 | 作業中 |
| 応答完了 | 一時的な手振り |
| 応答失敗・停止失敗 | 一時的な失敗ポーズ |
| 左右へのドラッグ | 左右へ走る |
| クリック | 手振り |

会話への反応は現在開いているチャットの既存ライフサイクルを参照します。この連動のための新しいチャットAPIや監視処理は追加しません。ジャンプ・レビューはプレビューで確認でき、独自にタスク状態を推測して再生しません。チャットから離れた場合は購読を解除し、待機へ戻ります。OSの「動きを減らす」または「アニメーションを抑える」で静止表示になり、非表示タブでは再描画を止めます。

## 永続保存先・バックアップ

既定の保存ファイルはリポジトリルートの `data/web-pets/registered-pet.asset` です。定義と画像を一つのファイルへ格納し、検証済みファイルを同じディレクトリで作成・同期してからアトミックに切り替えます。保存失敗時に先に旧ファイルを消す処理はありません。小さな登録情報だけを読み出せる構造なので、定期確認で画像本体を毎回転送しません。

保存先を分離する場合はNext.jsサービスへ `AOITALK_PET_DATA_DIR` を絶対パスで設定します。通常のサービス再起動で設定を変えないでください。ソースツリーの場所が変わるリリース切替、コンテナ再作成、複数Next.jsプロセスを使う構成では、全プロセスから同じ永続ディレクトリを参照するよう設定・マウントしてください。メモリ内や `.next`、ブラウザキャッシュへフォールバックしません。

`data/web-pets` または明示指定したディレクトリをバックアップ対象に含めてください。この本体はPostgreSQLには格納していないため、DBだけのバックアップには含まれません。`registered-pet.asset` はユーザー資産であり、Gitや公開配布物へコミットしません。停止のタイミングによって残った `.upload-*.tmp` は登録とはみなさず、再起動時に自動登録しません。必要な掃除はサービス停止中に一時ファイルだけを対象にしてください。

## 認証・プロファイル・安全性

WebUIとAPIの両方で利用を制限します。APIは有効なWebセッションと、Python runtimeが返す `application_features.entertainment === true` を要求します。`AOITALK_PROFILE` または `AIVTUBER_ENV` がEnterpriseの場合も拒否します。利用可否を確認できない場合は許可しません。登録状態の取得・画像配信・置換・削除のすべてがこの対象です。利用可能なログインユーザーは共通ペットを変更できます。

ZIP検証は従来のブラウザ実装を維持し、サーバーには定義と画像だけを送信します。サーバーでも送信内容を独立して検証します。受信ストリームの実サイズを制限してからmultipartを解析し、manifestとPNG / WebPの形式・寸法を検査し、Sharpで実デコードした静止画像のみを正規化PNGとして保存します。元のファイル名でサーバーのパスを生成せず、ZIP展開・任意ファイル参照・コード実行は行いません。変更APIは非単純ヘッダーを必須とし、別サイトからの変更を拒否します。

## 対応形式

`pet.json` の `spriteVersionNumber: 2`、`displayName`、`spritesheetPath` を使います。画像は1536×2288 px、8列×11行、1コマ192×208 pxの静止PNG / WebPです。コマ数は待機6・右走り8・左走り8・手振り4・ジャンプ5・失敗8・返答待ち6・作業6・レビュー6・視線16（最終2行）です。

ZIP32 MiB、画像12 MiB、定義16 KiBが上限です。ZIPは非暗号化のStore / Deflateに対応し、`pet.json` は1つだけ必要です。ZIP64・分割ZIP・特殊圧縮・絶対パス・パストラバーサル・重複パス・CRC不一致を受け入れません。ブラウザがDeflateに対応しない場合は手元で展開し、定義と画像を同時選択してください。Codex v1や別寸法の独自形式は対象外です。

対象はWebUIです。Androidネイティブ版への追加やWindowsデスクトップ常駐化は含みません。

## 検証

`frontend` 内で以下を実行できます。既存の依存関係のみを使います。

```sh
node --test tests/pets-contract.test.mjs
node --test tests/pets-server.test.mjs
npx vitest run src/lib/pets/__tests__/
npx playwright test e2e/pets.spec.ts
```

従来のcontractテストはZIP安全性・モーション・チャット配線を検査します。サーバーテストは厳密なTypeScriptチェックに加え、実際のSharpデコード、実ファイル保存、別プロセスでの再読み出し、Request/Responseハンドラー、認証拒否・feature判定、容量制限、置換・削除、保存失敗時の保持、同時新規登録を検査します。既存のペットやサーバーデータには触れず、合成画像と一時ディレクトリだけを使います。

`e2e/pets.spec.ts` は登録APIをテスト内の共通ストアでモックして、独立ブラウザcontextからの認識・反映、表示設定、既存UI操作を検査します。

実認証・実API・実ファイル保存を通した検証は、repo rootから次の専用ハーネスで実行できます。Pythonのテスト用依存関係（pytestを含む）、frontendの依存関係、Playwright Chromium、PostgreSQLの実行ファイルが必要です。

```powershell
venv/Scripts/python.exe scripts/verification/web_pet_qa.py prepare
# prepare が出力した manifest.json の絶対パスを指定
venv/Scripts/python.exe scripts/verification/web_pet_qa.py verify --manifest <manifest.json>
venv/Scripts/python.exe scripts/verification/web_pet_qa.py cleanup --manifest <manifest.json>
```

既存の隔離QA環境構築処理を再利用し、専用PostgreSQL DB、frontendのソースコピー、専用ペット保存ディレクトリを作成します。認証情報はrootの `.env.qa-login` を読み、通常のログイン画面からログインします。通常のDBや登録ペットは変更しません。`verify` が途中で失敗した場合も、最後に `cleanup` を実行してください。ログと認証後のスクリーンショットはmanifestと同じディレクトリに残ります。

`e2e-live/pets.live.spec.ts` は、独立クライアント、スマートフォン相当のviewportとtouch環境、Cookie・IndexedDB等を含むサイトデータ全削除、通常チャット画面での常時表示、表示サイズ・プレビュー・手振り・ドラッグ・アニメーション抑制、置換の定期反映、不正ZIP・不正画像による既存登録の保持を確認します。その後ハーネスがNext.jsとFastAPIの両プロセスを停止・再起動し、起動時刻が変わったことと同一登録の保持、サーバー登録削除の他クライアントへの反映を検証します。

インストール済みの別ブラウザでも確認する場合は、`verify` に `--second-browser-channel msedge` または `--second-browser-channel chrome` を追加します。指定しない場合はChromiumの独立contextを使います。スマートフォンの検査はエミュレーションであり、別の物理端末を操作した検証とは区別してください。チャットの応答待ち・生成・完了等の連動は既存の状態管理・WebSocket hookのテストでも確認し、実LLMへのリクエストはこのハーネスでは発行しません。
