# AI WebUI QA

WebUIの完成判定では、コードレビューやtypecheck / buildだけでなく、ユーザーが実際に操作した結果を確認する。共通の作業・CI・完了状態は [AGENTS.md](../AGENTS.md) を参照する。

## 対象

画面の表示・入力・保存・遷移・権限・ローディング・エラー復帰を変える作業、WebUIで再現した不具合、API変更によってWebUIの挙動が変わる作業が対象。文書のみ、テストのみ、挙動を変えない機械的整理は対象外にできる。

ユーザーが今回の依頼で `debugなし` を指定した場合は実環境QAを省略する。変更範囲のターゲット検証は省略しない。

## 担当と確認

実装担当がターゲット検証を行い、実装担当とは別のAIが実ブラウザで対象フローを操作する。担当モデルや委譲方法は利用環境のSkill・ツール定義に従い、ここでは固定しない。QA担当は最終差分レビューを兼任してよいが、差分レビューや既存E2Eだけで実ブラウザQAを代替しない。

毎回アプリ全体を総当たりせず、変更したフローと隣接する回帰を最低1件確認する。例えば日付編集なら、ログインから対象を開く、編集、保存、再読込して値の保持を確認するところまで行う。

画面の状態に加え、変更に関係するConsoleエラー、失敗したNetwork request、保存後の状態、エラー復帰を確認する。Backend logへアクセスできる場合は関連するERROR / Tracebackも確認する。

## ログイン

QA認証情報の保存先はrepo rootの `.env.qa-login`。存在する場合はそれを使ってAI自身がログインし、ユーザーに同じ情報を聞かない。Playwright / Computer Use / browser QAは同じ認証情報を使う。認証情報の値はログ・報告・commitへ出力しない。

ログアウトやセッション切れでは再ログインする。解消できない認証障害は原因と未検証の範囲を報告する。「修復」の名目で既存アカウントの権限や認証方式を勝手に変更しない。

## 不具合と回帰テスト

FAIL時は再現手順、期待結果、実際の結果、関連するConsole / Network / Backendの証拠を返す。原因の推測と観測事実は分ける。修正後は再確認し、安定して再現できる不具合は既存テストの不足分だけを `frontend/e2e/` の回帰テストへ追加する。

一度限りの操作コードや画像・ログは追跡しない `.local/` に置く。再実行できる回帰テストだけを恒久的なテストスイートに残す。検証用に起動したプロセスは終了時に停止する。

## 結果

| QA結果 | 報告 |
| --- | --- |
| PASS | 独立QAが実ブラウザで確認したフローと結果を記載する |
| FAIL | 不具合を修正して再QAする。未解決なら `INCOMPLETE` |
| 必要なブラウザ・認証・起動環境がなく未実施 | `INCOMPLETE_WEBUI_UNVERIFIED`。静的検証やbuild成功を実UIのPASSに置き換えない |

実装・ターゲット検証・実UI QA・commit / push・CIは別の結果として報告する。実UI未検証を理由に変更をpushせず黙って終了するのではなく、pushの結果と残る検証を明記する。
