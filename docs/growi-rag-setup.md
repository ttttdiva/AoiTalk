# 社内Wiki (GROWI) を RAG 取り込みする手順

AoiTalk のナレッジソースに GROWI 社内Wiki を登録すると、Wiki ページの本文が
bge-m3 + Qdrant のハイブリッド検索インデックスに取り込まれ、Agent の Knowledge 検索で
出典URL付きの回答ができるようになります。

## 1. 情シス（IT 管理者）に依頼すること

GROWI 連携には以下が必要です。社内の情シス担当へ依頼してください。

1. **GROWI の API トークン（access token）**
   - 取得元: GROWI の「個人設定（User Settings）> API Token」。
   - トークンは「そのユーザーが読めるページ範囲」しか取得できません。
   - 機密ページを取り込みたくない場合は、**全社公開ページだけ読める専用ユーザー**を
     作ってもらい、そのユーザーのトークンを発行するのが安全です（権限を絞れば
     機密ページがインデックスに混入しません）。

2. **GROWI のベースURL**
   - 例: `https://wiki.example.co.jp`
   - AoiTalk サーバー（FastAPI が動くマシン）から **このURLへ HTTP で到達できる**
     ことを確認してもらってください。社内ネットワーク内なら通常は到達可能です。

3. **ネットワーク・証明書の確認（必要な場合のみ）**
   - 社内プロキシ経由でしか到達できない場合は、その情報。
   - GROWI が社内認証局（社内CA）の証明書を使っている場合は、その旨。

> 要約すると、情シスに渡してもらうのは **「GROWI の URL」** と
> **「API トークン」** の 2 点です。トークンは取り込み範囲を絞るために
> 専用ユーザーで発行してもらうのが推奨です。

## 2. AoiTalk への登録手順

1. AoiTalk の設定画面 > 「ナレッジソース」を開く。
2. 「AgentのKnowledge検索を有効にする」にチェック。
3. 「GROWI追加」ボタンを押す。
4. フォームに入力する。
   - 表示名: 任意（例: 社内Wiki）
   - GROWIのURL: 情シスから受け取ったベースURL
   - APIトークン: 情シスから受け取ったトークン
5. 「接続テスト」で疎通を確認する。
6. 「追加して同期」を押す。初回は全ページを取り込むため時間がかかります。

## 3. 仕組みと運用

- **取り込み対象**: ページ本文（Markdown）。`/trash/*` と `/user/*` は既定で除外します。
- **差分同期**: 各ページのリビジョンID（無ければ更新日時）を保持し、変わっていない
  ページは本文を再取得しません。再同期は「Sync」ボタンで実行します。
- **出典URL**: 検索結果には GROWI ページへのリンクが付きます。
- **トークンの保管**: API トークンは DB に暗号化して保存されます
  （`knowledge_sources.growi_api_token`、アプリ層で AES-GCM 暗号化）。
  API レスポンスにトークン平文は一切含まれません（`has_api_token` の真偽のみ）。
- **アクセス制御**: 取り込んだ内容は AoiTalk 側のナレッジソース権限
  （`KnowledgeSourcePermission`）で閲覧範囲を制御できます。

## 4. うまくいかないとき

- 接続テストで 401: トークンが無効。情シスに再発行を依頼。
- 接続テストで 403: トークンの権限不足。読み取り可能なユーザーのトークンか確認。
- 接続テストで接続失敗: AoiTalk サーバーから GROWI URL へ到達できていない。
  プロキシ・ファイアウォール・URL を情シスと確認。
- 取り込みページ数が 0: GROWI のバージョンによって API 形が異なる場合があります。
  ナレッジソースの `access_policy.growi_endpoints`（`list` / `page`）で
  エンドポイントを差し替え可能です。
