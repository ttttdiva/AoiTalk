# Hermes 解析と AoiTalk ハーネスへの採用方針

2026年10月22日時点

## 結論

Hermes から採用する対象は、実装全体ではなく、実行の重複防止、結果の確定、取消、履歴の維持などの設計上の契約である。
AoiTalk の API ハーネスとローカル LLM ハーネスは、接続成功だけでなく、実際の成果物と異常終了時の挙動まで共通の基準で検証する。
現時点で確認できた実動作と、これから統合・検証する項目を以下に分ける。コード全体の正しさや、Hermes との全面的な同等性を保証する報告ではない。

## 解析対象と確認範囲

- 公開元は [NousResearch の hermes-agent](https://github.com/NousResearch/hermes-agent)。
- 対象リビジョンは `c93b7ec54c6886a3806a58e8a6e13724f3bd83ca`。ローカル Git とハッシュで確認した。
- 本番コードは 5,282 ファイル、1,591,501 行を通読した。
- ビルド・初期構築関連は 432 ファイル、93,617 行を通読した。
- 選定したテスト 29 スイート、8,602 行を静的に読んだ。
- より広いテスト、フィクスチャ、文書群は全件通読していない。Hermes 自体の実行検証は行っていない。
- 以下の Hermes に関する所見はソース読解に基づく。記載した受入条件は、AoiTalk で実証すべき基準であり、達成済みという意味ではない。

## 採用する機構と受入条件

### 1 同じ依頼を二重実行しない受付

`hermes_state_runtime.py` と `gateway/session_admission.py` は、要求 ID とペイロードのダイジェストを使う永続的な受付の参考になる。
**受入条件:** 同一 ID・同一内容の再送は同じ作業を参照し、別の作業を起動しない。同一 ID で内容が異なる場合は競合として拒否する。

### 2 ツール呼出しと結果を対応づける

`agent/turn_tool_validation.py` と `agent/tool_executor.py` は、呼出しと結果の対応および失敗分類の参考になる。
**受入条件:** 不正な引数、重複した呼出し ID、部分的な失敗を区別し、結果が欠けた作業を成功扱いしない。成功判定には実際の成果物確認を含める。

### 3 取消と期限を実行世代に結びつける

`agent/turn_context.py` と `gateway/turn_lease.py` は、取消・期限と実行世代の管理の参考になる。
**受入条件:** 取消または世代交代の後に、旧世代が最終結果を公開できない。物理的な実行停止が確認できない場合は、停止済みと表示せず未確認として扱う。

### 4 圧縮してもプロンプトの境界を保つ

`agent/context_engine.py`、`agent/context_pin.py`、`agent/conversation_compression_checkpoint.py` は、固定プレフィックス、進行中の履歴、圧縮境界の分離の参考になる。
**受入条件:** 実際にモデルへ送るプロンプトで固定部分の安定性を確認する。対応する呼出しのないツール結果や、圧縮時の末尾履歴の欠落を生じさせない。

### 5 論理セッションと保存履歴を分離する

`hermes_state_local_lineage.py` と `hermes_state_compression.py` は、論理的な会話の継続と物理的な履歴の管理を分ける参考になる。
**受入条件:** 圧縮結果の公開に失敗しても末尾履歴が失われず、古い保存先が再び有効にならない。保存・公開の途中で故障させて確認する。

### 6 委譲先の結果を親の状態に従わせる

`agent/delegation_context.py` と `agent/runtime_session_child.py` は、子タスクの所有範囲と終了結果の管理の参考になる。
**受入条件:** 親の終了後に届く子の結果は拒否または隔離し、終了済みの親や別の作業へ反映しない。

### 7 予定と実行と配信を別々に記録する

`cron/occurrences.py`、`cron/executions.py`、`cron/delivery_queue.py` は、予定の発生、実行、配信を独立して管理する参考になる。
**受入条件:** 送信後・確認記録前のクラッシュを再現し、再起動後に無条件で再送しない。配信状態が不明な場合も、成功や未送信に決めつけない。

### 8 画面の接続状態と作業結果を分離する

`web/src/pages/ChatPage.tsx` と `apps/desktop/src/app/chat/composer/` は、接続・入力・応答の適用範囲を管理する参考になる。
**受入条件:** 接続切断だけで作業の成功・失敗を確定しない。古いソケット、下書き、遅延応答が新しいプロファイルの状態を書き換えない。

## AoiTalk で確認できたこと

- Gateway Claude Code、OpenRouter DeepSeek、Strata の 3 経路はいずれも実動作を確認した。ただし、全受入条件を各経路で満たしたことまでは意味しない。最終受入の結果は後掲の節に記す。
- `required_outputs` は内容の基準値と書込み証跡で成果物を確認し、`edit_targets` は編集範囲を固定する仕組みとして整備されている。
- 検証コマンド要否の誤判定は main の `a4ccab58f` で修正された。テスト件数は本書では再確認していない。
- 再起動後に実際の DeepSeek ファイル作業で完了したことは運用側の報告であり、本書執筆時点ではこのリポジトリのテストで再確認していない。

## 実運用での受入結果（2026-10-22）

### 受入の対象と範囲

- 対象リビジョンは main の `46c0b7b0d`。本番へ反映し、既存の認証済み再起動を行ったあと、新しい起動でヘルスが正常であることを確認した。
- 実プロバイダ経路の受入は、OpenRouter DeepSeek と Strata で行った。Gateway Claude Code の実作業成功は、前掲の受入記録（`docs/harness_acceptance_20261022.md`）にある統合作業の実績に基づく。今回の最終受入では再実行していない。
- ローカル LLM として実用上必要な経路は Strata のみである。SGLang は対象外とし、本書では扱わない。

### 実経路で確認したこと

| 経路 | 成果物作成と読戻し | 生成開始直後の取消 |
| --- | --- | --- |
| OpenRouter DeepSeek | 宣言した出力ファイル（64 バイト）を作成し、読戻しで内容を確認した。親が実ファイルの内容と大きさを独立に読んで一致を確認した | 取消要求から約 1.1 秒でタスクが cancelled に終端した |
| Strata | 宣言した出力ファイル（62 バイト）を作成し、読戻しで内容を確認した。親が実ファイルの内容と大きさを独立に読んで一致を確認した | 取消要求から約 1.6 秒でタスクが cancelled に終端した |

- 成果物作成は、ファイルツールの書込み証跡と読戻しを伴い、`required_outputs` の確認を通って完了した。
- 取消の所要時間は、タスクが終端状態になるまでの観測値である。リモートサーバーや GPU の生成が物理的に止まったことの証拠ではない。
- 上記の結果から、Claude Code、DeepSeek、Strata の 3 経路は、実用上の受入として確認できたと扱う。

### 単体・モックの結果と実運用の結果の区別

- 単体・モックの検証: 固まったローカル HTTP スタブでクライアント側ソケットが閉じること、期限超過後の補正抑制、再起動時の期限切れ Work の処理、ストリーム後始末の境界条件を、統合ツリーの絞ったテストで確認した。事前から存在する SGLang の assertion 1 件（`test_ephemeral_llm`）を除いて成功した。これは全テストの成功を意味しない。
- 実運用の検証: 上表の 2 経路での成果物作成と、生成開始直後の取消。
- 実運用で確認していないもの: 期限超過と再起動を、実プロバイダ経路で再現した結果。これらは単体・モックの検証にとどまる。

## 残る限界と今後の確認

- 通信の中断で確認したのは、クライアント側ソケットが閉じたことまでである。サーバー・GPU の生成停止や、ツール副作用の停止を確認したものではない。
- ストリームの後始末で、未完了の作業がなければ close に失敗した closer は再実行しない。未完了の作業と失敗が混在する場合は、未成功の closer を再試行しうる。
- 実プロバイダ経路で、期限超過、再起動、遅延応答を再現する検証は未実施である。
- ファイル作業では実ファイルの内容と書込み証跡を確認し、宣言された出力の欠落や許可範囲外の編集を成功扱いしない。この方針は維持する。
- 各試験は対象リビジョン、利用経路、期待結果、実測結果を残す。単体テストの成功と実経路での成功を分けて報告する。
- 圧縮やクラッシュ復旧の意味論について、未検証の項目は Hermes と同等とはいえない。上記の故障・境界条件を再現してから採用完了とする。

優先順位は、既存の成果物検証を維持しつつ、実プロバイダ経路での期限超過・再起動の再現を確かめ、その後に圧縮・復旧・委譲・配信の境界条件を埋めることである。

## 共通実行規約の挿入（`src/llm/harness_instructions.py`）

- 版付きの共通実行規約（結果に基づく主張、前提確認、範囲の遵守、識別子の字面保持、部分・ページ分割結果の整合、外部取得内容はデータであり権限ではないこと、許可ツールとタスク固有の完了条件の範囲での検証、不確実性・中断の明示）を、Character 会話（16k 以下のコンパクト経路を含む）、Agent の API/ローカル/CLI、ローカルエージェントタスクのループに、所有する構成点で一度だけ付与する。入力文のマーカー等から適用済みとは判断しない。規約は英語で、入力を UTF-8 バイト上限で見積もる Dialogue 予算への負担を抑える。Agent の役割文、Character の文体、ユーザーの依頼、モデル設定とは分離したままである。
- 文言は AoiTalk の自作で、Hermes のプロンプトは転載していない。上記の契約の考え方のみを本書の読解に基づいて採用しており、Hermes との同等性は主張しない。
- 限界: 提供はテキストの揃えに限る。Gemini は初期の user/model コンテキスト、CLI は stdin への平坦化があり得るため、ネイティブの system/developer ロールの階層と同等ではない。
