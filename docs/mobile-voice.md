# モバイルの音声会話

チャット入力欄の「音声会話」から開始する。音声機能にはAoiTalkサーバーへの接続とログインが必要で、認識モデルやVOICEVOXなどの合成エンジンはスマートフォンには配置しない。

## 操作

- 初めて開始するときだけ、OSのマイク権限を確認する。通常のチャット画面を開いただけでは録音しない。
- マイクと読み上げはそれぞれ独立してミュートできる。マイクを拒否・ミュートしていても、文字で入力した内容への返答を読み上げられる。
- 音声モード中も文字入力と送信は使える。認識した発言は通常のチャット送信経路へ渡すため、既存のモデル選択・プロジェクト・会話履歴を引き継ぐ。
- 発話後の無音で認識へ進む。無音だけの録音は送信しない。1回の録音は最大30秒。応答の生成中と読み上げ中はマイクを一時停止し、スピーカーの音を次の発言として送らない。
- 読み上げ対象は、開始後に完了した新しいアシスタントの返信。過去の履歴、生成途中、失敗した返信、非アクティブな分岐は読まない。長い返信は分割し、コード・URLなどは音声向けに整える。
- 「×」、別の会話への移動、ログアウト、切断で録音・再生を停止する。アプリをバックグラウンドへ移すと両方をミュートし、戻っただけでは録音を再開しない。

## サーバーの設定

音声認識はサーバーの `speech_recognition` 設定、読み上げは返信したキャラクターの音声設定を利用する。Gemini TTS などのクラウドTTSもサーバー側で合成したWAVを返すため、アプリ側の追加設定は不要（[Gemini TTS](gemini_tts.md)）。VOICEVOXの起動パスは通常の `Config.voicevox_path` と同じ設定・環境変数・標準配置の解決規則を使う。音声認識のモデルが未取得の場合は、サーバー側で初回取得・読み込みが必要になる。認識・合成が利用できない場合も文字入力は失わない。

録音変換にはサーバーの `ffmpeg` が必要。アプリはAAC/M4Aを最大2MBで送り、サーバーで16kHz・モノラルPCMへ変換する。録音一時ファイルは認識・中止後に削除し、合成したWAVもスマートフォンでの再生後に削除する。録音を保留送信キューへ永続保存することはしない。

## API

`GET /api/mobile-voice/capabilities` が音声入力・出力の利用可否を返す。`POST /api/mobile-voice/transcriptions` が録音を認識し、`POST /api/mobile-voice/speech` が文字列とキャラクター指定からWAVを返す。いずれも通常のモバイル認証を使い、会話・プロジェクトを指定したリクエストでは書き込み権限を検証する。

アプリは開始時のサーバー識別子にリクエストを固定し、接続先切り替えで別サーバーへ録音を誤送信しない。同じ会話のローカルIDからサーバーIDへの昇格は音声モードを維持し、その後のリクエストには昇格後のIDを使う。サーバー側では認識と合成をそれぞれ直列化し、切断やタイムアウトの後も処理中のネイティブ資源を並行再利用しない。
