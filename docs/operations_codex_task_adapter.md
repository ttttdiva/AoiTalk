# Codex task inference adapter

`src/llm/codex_task_completion.py` provides a completion backend for the existing Operations task runner. The existing host route uses host authentication. The separate app-profile route described below is disabled by default; its concrete fixed-artifact login connector is a source checkpoint, with deployment and real acceptance still pending. The task runner and ToolGuard execute every declared dynamic tool. No authentication file is exported or mounted into a guest.

## Supported execution contract

The app-server protocol and temporary-thread settings support the explicitly reviewed official Codex releases 0.159.2 and 0.160.0. Both the daemon preflight and owned inference child reject every other release, including patch releases and prereleases. On Windows the official npm alias metadata resolves the native executable and must match its parent release; no Windows wrapper is executed under WSL. The process starts suspended, joins an owned kill-on-close Job Object, then resumes. All cleanup applies only to this owned process tree. A bounded writer and independent cleanup deadline allow cancellation and timeout to finish even when the peer stops reading stdin.

The adapter disables host execution features, plugins, legacy notify hooks, MCP connections, and remote control for this process/thread. Before launching the owned child it rejects any existing or unreadable Codex environments.toml registration and any unverifiable/symlinked Codex home. It never reads or changes that registry. The child alone receives CODEX_EXEC_SERVER_URL=none and has the four Noise environment connection keys removed. This startup check assumes no concurrent external edits to Codex home; it does not establish the separate managed-provider/account preflight. It uses an ephemeral thread with no attached execution environment and only the tool declarations supplied by the task runner. Unknown RPC requests, native execution items, mismatched thread/turn ownership, missing tool results, route changes, and non-final-only replies fail closed. Harmless model-provided utility tools are not claimed to be universally absent.

Existing ChatGPT authentication stays in the official host CLI. Public account metadata (email, workspace ID, backend origin) is checked before a turn, every tool-result return, and final completion. This detects observed account changes; it does not prove an undisclosed stable user ID. No tokens are read by this adapter.

## Required deployment preflight

Before starting an authenticated app-server, verify that managed configuration does not force a non-OpenAI provider or unapproved origin. Managed requirements take precedence over CLI overrides, and app-server model refresh can run during startup. Process-local endpoint pins alone do not establish this precondition. Do not bypass managed requirements. An already-running official daemon can expose `configRequirements/read`; do not start a new daemon merely to evade this preflight.

By default, host instructions are rejected before the first model turn when the thread reports inherited instruction sources. The explicit one-task host review below is the only exception, under the existing trusted-host deployment premise. App-profile tasks always require empty instruction sources and cannot use that exception. Unknown CLI versions are unsupported. Global CLI configuration and authentication are never modified.

Managed OpenAI definitions containing `model_catalog_url` or `modelCatalogUrl` are rejected. Codex 0.160.0 activates explicit provider catalogs in its models manager; Operations has no reviewed contract for a custom catalog origin. This check also rejects malformed or future definitions even though the official requirements loader currently rejects definitions for the reserved `openai` provider ID.

## Runner integration

`CodexTaskCompletionClient` implements `describe`, `build_request`, `complete`, `message_content`, and `close`. It takes an explicit model, effort, canonical workspace, timeout, cancellation callback, and optional owner checkpoint. The checkpoint must preserve the task runner cancellation/deadline exception so the application reports `cancelled`, not a generic runtime failure. The adapter returns dynamic tool requests and waits for matching guarded results; it never directly executes tool arguments.

The task API accepts optional provider/model/effort and preserves the requested route alongside its resolved route. An omitted route retains the existing local configuration. Explicit local models are validated against the existing catalog; Strata task requests default to thinking. The Codex route requires a trusted server-side preflight callback and remains unavailable when that callback is absent. Ordinary API callers cannot enable it or bypass preflight. Codex command tasks additionally require a server-issued execution scope. Do not advertise app-level Codex readiness based only on the adapter tests.
